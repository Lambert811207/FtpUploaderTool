# FtpUploaderTool（VS2010 + MFC）

这是按 `FTP自动上传工具_开发文档.md` 重建的 **Visual Studio 2010 SP1 / MFC Unicode 对话框程序**。解决方案和程序名均为 `FtpUploaderTool`，支持 Win32 和 x64，工程配置使用 v100、静态 MFC、静态 CRT。Win32 最低目标为 Windows XP SP3，x64 最低目标为 Windows XP Professional x64（系统版本 5.2）。

## 构建

在安装 VS2010 的开发人员命令提示符中运行：

```bat
build.cmd Release
build.cmd Release x64
build.cmd Debug x64
```

或者打开 [FtpUploaderTool.sln](FtpUploaderTool.sln)，选择 `Release|Win32`、`Debug|Win32`、`Release|x64` 或 `Debug|x64` 后生成。Win32 输出到 `Release` / `Debug`，x64 输出到 `x64\Release` / `x64\Debug`，两种平台使用独立的输出及中间目录。

`build.cmd` 默认构建 Win32，第二个参数指定 `x64` 时使用 VS2010 的 x64 交叉编译环境；均使用 .NET Framework 4.0 MSBuild，不依赖新版本 .NET。项目源文件使用 UTF-8 BOM；资源脚本使用 UTF-16 LE，VS2010 可直接打开。

## 代码结构

主窗口负责交互和显示；`TaskManager` 统一管理任务配置与工作对象、数量/冲突校验、保存及批量启停。新增、编辑、删除和勾选先保存成功再更新内存，保存失败不改变已有任务或消耗任务编号。

`TaskEditDlg` 和 `SettingsDlg` 分别实现任务配置与系统设置；`ConnectionTest` 管理连接测试的开始、取消、状态快照和异步资源释放，窗口不直接操作测试对象的引用计数。`DialogHelpers` 共用参数提示处理，`ConfigLimits` 共用参数边界，`TaskConfig::Validate`、`GlobalConfig::Validate` 返回首个参数错误。

退出时先请求任务和远程临时文件清理线程停止，定时检查完成后写入退出日志，再请求日志线程排空队列并回收。正常退出流程不在主窗口线程同步等待网络清理或日志写盘；析构保留最终回收，原有 8 秒退出超时策略继续有效。

## 运行

程序在运行、保存配置和上传时，会按需在 exe 目录创建：

```text
Config\FtpUploaderTool.ini
Data\History_<任务 GUID>.txt
Data\RemoteTemp\<记录 GUID>.ini：尚未确认清理完成的远程临时文件
Log\SystemLog.txt、Task1Log.txt、Task2Log.txt…，以及对应的 Task1Log.backup1.txt… 归档文件
Dump\FtpUploaderTool_*.dmp
```

配置文件不存在时程序使用空任务列表启动；在界面点击“新增任务”填写服务器、账号、本地目录、远程目录和策略。FTP 密码在编辑框中直接显示，配置文件使用 `PasswordPlain` 字段明文保存；旧版 DPAPI 密码成功读取后自动迁移为明文，解密失败时保留原配置并提示错误。程序每个任务使用独立 `_beginthreadex` 工作线程，UI 线程只读取状态快照和有界日志队列。任务列表首列的勾选状态决定是否参与上传，并随配置保存；新任务和旧配置默认勾选。程序启动时自动运行已勾选任务，“全部启动”也只启动已勾选任务，“全部停止”停止所有任务。

新配置使用 `TaskCount`、`Task0…` 和 `[Task_<GUID>]`；旧版 `ChannelCount`、`Channel0…`、`[Ch_<GUID>]` 仍可读取，保存时转为新格式。旧 `Enabled` 字段不再使用。

新任务的“上传文件名规则”默认为 `*`，“排除文件名规则”默认为空，“扫描本地子文件夹”默认开启，“上传成功后”默认为“删除本地文件”；已有任务继续读取其保存的参数。上传文件名规则为空或 `*` 都匹配全部文件名，仍受排除规则、子文件夹范围、上传前文件不变时间及已上传记录等条件限制。不按文件修改时间的新旧筛选待传文件，旧配置中的 `MaxFileAgeDays` 字段会被忽略，重新保存时不再写出。

日志输出统一为 TXT，不再创建、追加或归档 CSV。已有 CSV 文件保持原样。

主界面支持：

- 主窗口固定大小，不提供边框拖动缩放、最大化或系统菜单中的调整大小命令；保留最小化和托盘操作。底部汇总状态栏已删除，任务执行状态继续在任务列表显示。
- 新增任务只保存配置并保持已停止，由“全部启动”开始运行；删除当前选中的任务行、双击已停止的任务直接编辑；运行或停止过程中禁用新增和删除，未选中任务时禁用删除。删除需确认，仅移除任务配置，保留本地文件。任务数量上限 32，达到上限后禁用新增按钮。
- 全部启动/全部停止；有任务运行或正在停止时，列表保留正常启用外观，拦截鼠标、键盘、双击和勾选，绘制及状态刷新照常进行，全部停止后恢复交互。运行时禁用全部启动；点击全部停止后，两按钮在停止完成前均禁用，停止完成后恢复全部启动。
- 系统设置、参数鼠标提示；任务名称进入配置时不自动全选，列表列宽按字体和表头文字计算。系统设置可配置单个日志大小上限（MB）和归档文件上限，日志仅按大小轮转及数量保留。归档改名失败（例如归档文件被日志查看工具占用）时继续写入当前文件，可能暂时超过大小上限，每分钟最多重试一次归档；中途失败留下的编号空位在下次归档时补齐，不会删除尚未轮到的归档。写入或归档故障按文件区分，不影响其他任务及系统日志。
- 连接状态、待传数、搁置数、今日成功/失败、当前进度和最后错误；状态列按状态着色，最后错误固定红色，其他列重置为正常颜色；日志时间包含年月日及毫秒。任务 1 的当前日志为 `Task1Log.txt`，归档为 `Task1Log.backup1.txt`、`Task1Log.backup2.txt`，backup1 为最新；系统日志使用 `SystemLog.txt`。上传明细与任务运行日志统一写入 TXT，并在界面显示；每次尝试记录本地完整路径、服务器目录及文件名、文件大小、耗时、成功/重试/失败结果及原因，成功时还记录平均速度。每个 TXT 系列分别保留指定数量的 backup，默认 10 个归档加 1 个当前文件，共 11 个。任务编号持久化保存，任务改名和删除后继续保持对应关系。
- 操作日志统一写入 `SystemLog.txt`，带 `[操作]` 标记，记录操作名称、任务编号/名称/ID、结果及失败原因。覆盖新增/编辑/删除任务、勾选及选择任务、自动和批量启停、配置保存、系统设置及应用结果、目录选择、连接测试及取消、日志筛选/自动滚动/复制/清屏/打开目录、窗口显示/隐藏/最小化、重复启动及退出。保存、取消和失败分别记录，密码值及复制的日志内容不写入操作日志；清屏只清除界面，磁盘操作日志保留。
- 勾选“自动滚动”后，新日志始终跟随到底部，手动滚动不会使该选项失效；重新勾选会立即到底部。需要查看历史日志时取消勾选，新增日志会保留当前滚动位置。
- 日志列表使用虚拟列表，每 200 毫秒批量刷新，默认保留 2000 行，最多 10000 行；界面待处理队列最多 5000 条，磁盘写入队列独立。取出界面日志时仅在锁内交换队列，复制和筛选在锁外执行，减少阻塞上传线程的时间。
- 日志列表的时间、任务、级别、内容四列均支持单元格提示，鼠标停留约 200 毫秒后显示指向单元格的完整内容；筛选、滚动及日志更新后同步更新提示。
- 通配符过滤、子目录扫描、文件稳定时间和写锁判断。
- PASV/PORT、UTF-8/GBK、临时名上传、SIZE 校验、RNFR/RNTO 原子改名。
- 临时上传使用 `_ftpupload_<GUID><后缀>`，完成后改为正式文件名；停止、退出、上传失败和取消连接测试时尝试清理。清理使用独立连接及 2 秒网络等待预算，失败记录由后台每轮间隔 10 秒重试，重启后仍可处理，无需源文件或原任务继续存在。清理记录保存原服务器、账号密码及精确路径，密码仍按要求明文保存；只删除已记录的临时文件，正在上传的文件及无记录的同后缀文件不会批量删除。断网或服务器拒绝删除期间仍可能暂留文件，恢复访问后重试；旧版已经存在且没有记录的残留需另行确认处理。
- 删除、移动到日期备份目录、保留并写历史记录三种后处理。“保留”策略下源文件持续保留，移动后的备份文件也持续保留，均不按天数自动清理。备份目录与监控目录在同一分区时直接改名移动（只读源文件同样移动）；跨分区时复制并落盘后再删除源文件，删除源文件失败则撤销本次备份副本，重试不会累积副本。删除或移动失败时，上传成功后立即尝试 3 次，之后按 30 秒、1 分钟、2 分钟……最长 10 分钟的间隔重试，第 1、2、4、8… 次失败记录原因；重试每轮最多占用约 2 秒，不再阻塞后续上传。
- 托盘隐藏、双击恢复、右键退出；关闭按钮和 Esc 只隐藏窗口。
- “测试连接”位于“监控及上传路径”组，直接启动后台测试，无开始确认弹窗：登录、进入/创建目录、上传 16 字节测试文件、校验并删除。过程和结果显示在同组按钮右侧，再次点击可取消；参数填写错误仍单独提示对应参数。

任务配置按“FTP 服务器”“监控及上传路径”“本地扫描及清理”“文件上传及处理”“连接维护及重连”分组。“本地监控目录”“服务器上传目录”明确本机与服务器位置；“扫描本地子文件夹”只影响本机上传扫描范围。文件名规则、子文件夹扫描、扫描间隔、上传前文件不变时间和旧空文件夹清理归入“本地扫描及清理”；单文件失败上限、成功后的本地文件处理、备份目录、同名文件处理、临时文件名及大小核对归入“文件上传及处理”。秒、次、天均使用输入框右侧的独立单位标签。服务器上传目录占位符说明放在鼠标提示中，界面不再显示整行占位符帮助文字。临时文件名后缀有独立标签，随“先用临时文件名上传”一起启用或禁用。

“自动删除旧空文件夹”是每个任务的独立选项，默认关闭，天数默认 7，允许 1–36500 天；关闭时天数输入及单位禁用。启用后，在任务启动时检查一次，此后每小时检查：只删除监控目录内最后修改时间早于 N×24 小时且当前为空的子文件夹，始终保留监控根目录。此项独立于文件名筛选和上传子文件夹开关，最多检查 10 层，跳过隐藏、系统及链接/重解析目录。使用普通空目录删除接口，检查后刚写入文件、被占用或其他删除失败时跳过并记录原因，不递归删除文件，不清理服务器或本地备份目录。

空目录天数依据文件夹最后修改时间，不记录连续空置时间；子目录删除后会重新读取父目录的时间。其他软件再次使用被清理的路径时需自行创建目录。配置键为 `DeleteOldEmptyDirs`、`EmptyDirAgeDays`，旧配置缺少这两项时保持关闭、7 天。新增/编辑任务成功保存时记录开关与天数；`SystemLog.txt` 还记录每轮开始、结束或取消、删除数量、目录路径、修改日期及失败原因。

被动模式（PASV）由本软件连接 FTP 服务器的数据端口；主动模式（PORT）由服务器反向连接本机的数据端口。两种模式的登录/命令连接都由本软件发起，只是数据连接方向不同。通常优先使用被动模式，服务器需开放被动数据端口；主动模式需允许服务器访问本机对应入站端口，经过路由器或防火墙时配置较复杂。

连接维护及重连参数分别为“连接建立超时”“数据收发超时”“连接状态检查间隔”“初始重连间隔”“最大重连间隔”“空闲断开时间”，单位均为秒，鼠标提示解释触发条件。连接状态检查在无文件上传时发送 NOOP 保活命令，失败后自动重连。数据收发超时限制单次网络操作或应答等待，不限制整个文件的上传总时长；初始重连间隔用于网络故障后的首次等待，连续失败逐次加倍至最大间隔并持续重试，登录失败直接使用最大间隔；空闲断开时间为 0 表示不主动断开。服务器填写域名时在后台线程解析，等待不超过连接建立超时，停止请求可立即中断；解析失败或超时时沿用本次运行中上次成功解析的地址。

“保留”策略通过 `Data\History_<任务 GUID>.txt` 持久化成功上传的文件记录。每条记录包含相对路径、大小和最后修改时间，写入并刷新磁盘后才确认上传成功。重新启动同一任务会读取该记录，三项均相同的文件不再上传；修改、重命名、重建任务或丢失对应历史记录可能使文件重新上传。当前使用文件元数据判断，不计算内容哈希，也不逐个查询远端文件是否仍存在。扫描时，目录枚举得到的大小和修改时间与记录一致的文件直接按已上传处理，不再逐个读取文件属性；其他文件仍读取精确属性判断是否稳定。扫描结束后才开始计算下一次扫描间隔，大目录扫描耗时较长时仍为上传留出间隔。

服务器同名文件严格按选定策略处理，不再根据“同名且大小相同”认定上传成功：覆盖会实际上传并替换，改名会实际上传到带修改时间标识的名称，不上传则暂停该文件并保留本地源文件。改名后的目标也存在时，同样暂停并保留源文件；服务器不支持同名状态查询时，改名或不上传策略报告原因并保留源文件。只有实际上传成功、完成已启用的校验及必要改名后，才写入成功历史并执行本地删除或备份。

旧版本曾把同名同大小文件写成成功记录，已有历史格式无法区分这些记录与真实上传记录。已有记录继续保留；旧版可能误记的条目需结合日志另行核对，修复不会自动恢复此前已删除的源文件。

界面不再提供编辑按钮、复制任务、单个任务启动/停止、重试失败按钮或任务配置中的启用选项。单文件达到“单文件失败上限”后暂停，该计数包含首次可计数失败，连接中断等网络错误单独重连；本地文件读取失败（例如所在磁盘或网络共享中断）按单文件失败计数，不进入网络重连，也不堵塞后面的文件。“不上传”策略下，只有服务器已有同名文件时首次即暂停，权限不足、服务器磁盘已满等其他错误同样按失败上限计数。点击“全部停止”，待任务停止后勾选该任务，再点击“全部启动”可重新尝试。

远程目录占位符：`{yyyy}`、`{MM}`、`{dd}`、`{HH}`、`{sub}`、`{pc}`；日期使用文件修改时间。数据连接和控制连接均有超时，停止事件以 200ms 分片检查；网络错误按配置的最小/最大间隔退避无限重连，默认 3/6/12/24/48/60 秒，每次失败均记录次数和下次重连间隔。日志线程不在工作线程写磁盘，队列有上限，磁盘故障不会阻塞上传；每批日志按目标文件合并，每个文件只打开一次。

上传、日志写入、连接测试和远程临时文件清理线程统一使用 `THREAD_PRIORITY_LOWEST`（相对优先级 -2），界面线程保持正常优先级；CPU 繁忙时后台任务优先让出处理器。该设置降低 CPU 调度优先级，不限制 CPU 使用率，也不改变进程或磁盘 I/O 优先级。

## 命名约定

资源 ID 使用控件类型及用途前缀，例如 `IDD_DLG_MAIN`、`IDC_BTN_ADD_TASK`、`IDC_BTN_TASK_OK`、`IDC_BTN_SETTINGS_CANCEL`、`IDC_GRP_LOCAL_SCAN_AND_CLEANUP`、`IDC_CHK_DELETE_OLD_EMPTY_DIRS`、`IDC_EDIT_EMPTY_DIR_AGE_DAYS`、`IDC_GRP_UPLOAD_FILE_HANDLING`、`IDC_GRP_CONNECTION_MAINTENANCE_RECONNECT`、`IDC_STATIC_CONNECTION_ESTABLISH_TIMEOUT_UNIT`、`IDC_LIST_TASKS`、`IDC_EDIT_TASK_NAME`。资源中的标签、分组框、单位及确认/取消按钮均使用独立 ID；`IDOK`、`IDCANCEL` 保留为 MFC 对话框返回值及键盘命令。

参数名称、校验提示、鼠标提示及资源 ID 保持对应；本次名称调整和 ID 对照见 [参数名称与资源ID检查.md](参数名称与资源ID检查.md)。原有 ID 的十进制数值保持不变，配置键、默认值和上传行为保持不变。

成员变量和文件作用域变量使用 `m_` + 类型前缀 + 驼峰名称，例如 `m_strRoot`、`m_listTasks`、`m_stConfig`；局部变量及参数使用类型前缀 + 驼峰名称，例如 `strPath`、`nIndex`、`bSuccess`、`pParent`。配置窗口代码位于 `TaskEditDlg.h/.cpp`。

中文注释使用独立行，放在对应类、函数、变量或处理逻辑的上方，不写在声明或语句末尾。注释重点说明参数单位及特殊值、资源所有权、线程协作、配置提交顺序和失败处理原因。
